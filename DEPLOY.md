# Deploying OpenEval (free tier)

Stack: Render (backend + Celery worker + frontend, all free web/worker
services) + Neon (free Postgres) + Upstash (free Redis) + Groq (free LLM API
for eval judging, keyless-by-default `judge_model` otherwise points at a local
Ollama that won't exist in the cloud).

All four services have a genuinely permanent free tier with no credit card as
of 2026. `render.yaml` in the repo root is a Render Blueprint — it defines all
three Render services in one file.

## 1. Create the data services (5 min, needs your own accounts)

- **Neon**: [neon.tech](https://neon.tech) → sign up → New Project → copy the
  `postgresql://...` connection string (use the *pooled* connection string,
  not direct).
- **Upstash**: [upstash.com](https://upstash.com) → sign up → Create Database
  (Redis) → copy the `rediss://...` connection string (TLS, note the extra
  `s`).
- **Groq**: [console.groq.com](https://console.groq.com) → API Keys → create
  one. Free tier, no card.

## 2. Deploy to Render

- [render.com](https://render.com) → sign up → New → Blueprint → connect the
  `openeval` GitHub repo. Render reads `render.yaml` and proposes three
  services: `openeval-backend`, `openeval-celery-worker`,
  `openeval-frontend`.
- Before applying, fill in the `sync: false` env vars on the two backend
  services (Render prompts for these during blueprint creation):
  - `DATABASE_URL` → the Neon pooled connection string
  - `REDIS_URL` → the Upstash `rediss://` string
  - `GROQ_API_KEY` → the Groq key
  - `JWT_SECRET` is auto-generated by the blueprint, no action needed.
- Apply. First deploy runs `alembic upgrade head` against Neon, then starts
  uvicorn; the worker starts `celery -A workers.celery_app worker`.

## 3. Fix the frontend → backend URL

`render.yaml` guesses the backend's URL as
`https://openeval-backend.onrender.com` for the frontend's
`NEXT_PUBLIC_API_URL` build arg. Render only guarantees that hostname if the
name `openeval-backend` wasn't already taken by someone else. After the
backend service is live, check its actual URL in the Render dashboard — if it
differs, update `dockerBuildArgs.NEXT_PUBLIC_API_URL` in `render.yaml` (or set
it directly in the frontend service's settings) and redeploy the frontend.

## Known free-tier trade-offs (accept or upgrade later)

- Render free web services spin down after 15 min idle; first hit after that
  takes 30–60s to wake up. Fine for a portfolio demo link, not for a live
  product.
- Neon free compute suspends after 5 min idle and cold-starts on the next
  query; 0.5 GB storage cap.
- Upstash free Redis: 500k commands/month, 256 MB. Plenty for demo traffic
  and Celery's broker/result backend.
- `judge_model` defaults to `ollama/llama3` locally; this deploy overrides it
  to `groq/llama-3.1-8b-instant` via `JUDGE_MODEL` in `render.yaml` so evals
  actually run without a local Ollama daemon. No code change needed — the
  eval engine already goes through litellm's `provider/model` string.
